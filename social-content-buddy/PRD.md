## 1. Product Overview

PostAI is an invitation-only SaaS platform that generates professional Instagram post designs for businesses using AI. Users organize their businesses into **workspaces**, each with a saved business profile and brand kit. The platform automatically generates:

1. **Design briefs** — Detailed visual layout instructions (hook category, caption, color palette, typography, layout specs) generated by Google Gemini by reading the actual business website
2. **Full captions** — Complete Instagram captions with hook line, body text (2-4 sentences with CTA), and 10-15 hashtags
3. **Post images** — 1080x1080px Instagram-ready graphics rendered by fal.ai's GPT Image 1.5 model
4. **Caption variations** — 3 alternative full caption options per post for A/B testing

The platform also supports **team collaboration** (invite members with roles), **post approval workflows** (draft → approved → scheduled → published), **workspace-scoped Instagram accounts**, and **timezone-aware scheduling**.

The entire process takes 1-3 minutes per batch and requires zero design skills from the user.

## 2. How It Works — End-to-End Flow

```
User selects workspace → Form pre-fills from profile → Brand kit injected →
Gemini reads website + generates design briefs with caption variations →
fal.ai renders images in parallel → Images appear in real-time →
User edits captions / schedules via calendar → Downloads or publishes
```

### Step 1 — User Selects Workspace & Submits Form
The user selects (or creates) a workspace, which pre-fills:
- **Business Name** (required, from workspace profile)
- **Website URL** (optional — if provided, Gemini actually fetches and reads the page)
- **Target Audience** (optional, from workspace profile)
- **Tone Preferences** (optional, from workspace profile)
- **Number of Posts** (1, 2, 3, 5, or 10)

Brand kit data (colors, fonts, guidelines) is automatically injected from the active workspace.

### Step 2 — Gemini Generates Design Briefs
- Model: `gemini-3-flash-preview` with URL context tool enabled
- System prompt: loaded from `bau/social-post-generator-system-prompt.md`
- Gemini reads the business website (if provided) and generates N design briefs
- Brand context (colors, fonts, guidelines) is injected into the prompt when available
- Each brief contains:
  - `hookCategory` — The psychological hook type (e.g. "The Comparison", "The Problem/Solution")
  - `captionHook` — Opening caption line (max 12 words)
  - `captionBody` — Full caption body (2-4 engaging sentences with CTA)
  - `hashtags` — Array of 10-15 relevant hashtags (mix of broad and niche)
  - `designBrief` — Full visual layout spec as a paragraph (colors, fonts, layout zones, imagery)
  - `whyThisWorks` — 1-2 sentences on the psychological mechanism
  - `captionVariations` — Array of 3 alternative full captions (each with hook + body, different angles)
- Briefs are saved to the database and returned to the frontend immediately

### Step 3 — Image Generation via SSE
- Frontend opens a Server-Sent Events (SSE) stream to `GET /api/generate/stream/{batchId}`
- Server runs `fal.subscribe("fal-ai/gpt-image-1.5", ...)` for all posts **in parallel**
- As each image completes (30-90s), the server pushes an SSE event to the browser
- The image card pops in immediately on the page — no waiting for all to finish
- Images are stored on Cloudflare R2 (if configured) or served directly from fal.ai CDN

### Step 4 — Post-Generation Editing & Publishing
- Users can **inline-edit** caption hook, caption body, hashtags, hook categories, and "why this works" text
- Users can **pick from caption variations** — 3 AI-generated full caption alternatives per post
- Users can **schedule posts** via the calendar's drag-and-drop interface with time picker
- **Approval workflow**: Draft → Approved → Scheduled → Published
- **Publishing**: Full caption (hook + body + hashtags) sent to Instagram via GetLate.dev
- Credits are deducted only after successful image completion (1 post = 1 credit)

## 3. User Roles & Access

### Standard User
- Signs up with an invitation code
- Gets **365 lifetime credits** (1 credit = 1 generated post)
- Can: Create workspaces, generate batches, edit posts, schedule via calendar, download images, invite team members
- Cannot: Access admin panel, manage other users, generate invite codes

### Workspace Roles (Team Collaboration)
- **Owner** — Full control: edit workspace, manage brand kit, invite/remove members, link Instagram accounts, delete workspace. Automatically assigned on workspace creation.
- **Editor** — Can generate posts, edit captions, schedule, approve, and publish within the workspace.
- **Viewer** — Read-only access to posts and calendar within the workspace.

### Admin User
- `is_admin = true` flag in the database
- Has all standard user capabilities PLUS:
  - `/admin` — Platform stats overview
  - `/admin/users` — View all users, toggle admin status
  - `/admin/codes` — Generate and manage invitation codes
  - `/admin/posts` — View all generated batches across all users
- First admin is created via the seed script (`npm run db:seed`)

## 4. Core Concepts

### Workspaces
A workspace represents a single business/brand. Each user can have multiple workspaces.

**A workspace contains:**
- **Business Profile** — name, website URL, target audience, tone preferences
- **Brand Kit** — up to 6 brand colors, heading/body fonts, free-text brand guidelines
- **Timezone** — workspace-level timezone for scheduling (e.g. "America/New_York")
- **Linked Instagram Account** — one Instagram account per workspace for publishing
- **Team Members** — owner + invited editors/viewers with role-based access
- **Associated Batches** — all post batches generated under this workspace

**Workspace behavior:**
- Active workspace is persisted in `localStorage` under key `postai_active_workspace`
- Switching workspaces filters the dashboard, history, and calendar views
- The create form auto-fills from the active workspace's business profile
- Brand kit data is injected into Gemini prompts for on-brand AI generation
- Workspaces can be created, edited, and deleted from the sidebar switcher and settings page
- Deleting a workspace sets `workspace_id = NULL` on associated batches (does not delete content)
- Instagram accounts are linked per-workspace (not globally) — each workspace publishes to its own account
- API keys (Gemini, fal.ai, GetLate) remain at user-level, not workspace-level

### Batches
A batch is a single generation run. Contains 1-10 posts, all sharing the same business context.

### Posts
A generated post within a batch. Contains:
- **Caption Hook** — Opening line (max 12 words)
- **Caption Body** — Full body text (2-4 sentences with CTA)
- **Hashtags** — Array of 10-15 tags
- **Design Brief** — Visual layout instructions for image generation
- **Rendered Image** — 1080x1080 Instagram-ready graphic
- **Caption Variations** — 3 alternative full captions
- **Approval Status** — Draft → Approved → Scheduled → Published
- **Scheduling Metadata** — `scheduledAt`, `publishedAt`, `instagramPostId`

### SSE Event Types (from `/api/generate/stream/[batchId]`)
```json
{ "type": "post_completed", "post": { "id", "imageUrl", "hookCategory", "captionHook", "designBrief", "whyThisWorks", "captionVariations" } }
{ "type": "post_failed", "postId": "..." }

```

### Calendar API
```
GET /api/posts/calendar?start=2026-03-01&end=2026-03-31&workspace=<uuid>
```
Returns all completed posts within the date range. Posts are matched by `scheduledAt OR publishedAt OR createdAt` falling within the range. Workspace filter joins through `post_batches.workspace_id`.

### Post Update API
```
PATCH /api/posts/:postId
Body: { captionHook?, captionBody?, hashtags?, hookCategory?, whyThisWorks?, approvalStatus?, scheduledAt? }
```
Ownership verified via `user_id` match. `scheduledAt` accepts ISO datetime string or null (to unschedule). `approvalStatus` supports: draft, approved, scheduled, published, rejected. `hashtags` is an array of strings.

### Publish API
```
POST /api/posts/publish
Body: { postId, accountId? }
```
If `accountId` is omitted, auto-resolves from workspace: post → batch → workspace → linked social account. Builds full caption as `hook + "\n\n" + body + "\n\n" + hashtags.join(" ")`.

### Team Invite Flow
```
1. POST /api/workspaces/:id/members  { email, role }  → Creates workspace_invites record (7-day expiry)
2. GET  /api/user/invites                              → Invitee sees pending invites
3. POST /api/workspaces/invites/accept  { inviteId }   → Creates workspace_members record
```
Email matching is case-insensitive. Duplicate invites and existing members are rejected (409).

## 9. Feature Details

### Inline Caption Editing
Available on: Create page, History detail page, Calendar detail modal.

- Pencil icon appears on hover over editable fields
- Click to enter edit mode (inline input/textarea replaces text)
- Save/Cancel buttons appear
- PATCH request to `/api/posts/:id` on save
- Optimistic UI update + toast notification
- Editable fields: `hookCategory`, `captionHook`, `captionBody`, `hashtags`, `whyThisWorks`
- Hashtags: displayed as inline violet tags, edited as one-per-line in textarea

### Caption Variations
- Gemini generates exactly 3 alternative full captions per post (each has hook + body)
- Stored as `captionVariations` jsonb array on `generated_posts`
- UI shows clickable variation cards below the main caption
- Clicking a variation replaces the active `captionHook` (PATCH to API)
- Each variation shown as a compact card with different angle/tone

### Drag & Drop Calendar Scheduling
- Uses native HTML5 Drag and Drop API (no external library)
- Post thumbnails (`PostMini`) have `draggable` attribute
- `onDragStart` sets post ID via `dataTransfer.setData`
- Day cells act as drop targets with `onDragOver` + `onDrop`
- Drop target visual: violet ring + background highlight
- On drop: PATCH `/api/posts/:id` with `scheduledAt` = noon on target date
- Local state updated immediately for responsive feel
- Toast notification confirms the move

### Brand Kit AI Integration
When a workspace has brand kit data, it's injected into the Gemini prompt:
- **Brand Colors** — Listed as hex values, design brief must incorporate them
- **Brand Fonts** — Heading and body fonts specified for layout instructions
- **Brand Guidelines** — Free-text instructions appended to the prompt

The design brief instruction explicitly states: "MUST incorporate the brand colors and fonts specified above".

### Post Approval Workflow
State machine: **Draft → Approved → Scheduled → Published**

- **Draft** — Default state for newly generated posts
- **Approved** — Owner/editor marks as ready. Unlocks Schedule and Publish Now actions
- **Scheduled** — Post has a `scheduledAt` date+time. Can be cancelled back to Approved
- **Published** — Post has been sent to Instagram. Sets `publishedAt` and `instagramPostId`

Calendar modal shows contextual action buttons based on current state:
- Draft: "Approve" button
- Approved: "Schedule" (requires date+time) + "Publish Now"
- Scheduled: "Cancel Schedule" (reverts to Approved, clears scheduledAt)

### Instagram Publishing
- Full caption composed as: `captionHook + "\n\n" + captionBody + "\n\n" + hashtags.join(" ")`
- Auto-resolves Instagram account from workspace chain: post → batch → workspace → linked social_account
- GetLate.dev API handles the actual Instagram API interaction
- Supports both immediate publish and scheduled publish

### Social Account Workspace Isolation
- **API keys** (Gemini, fal.ai, GetLate) — stored at **user level** (shared across workspaces)
- **Instagram accounts** — linked at **workspace level** (each workspace publishes to its own account)
- PATCH `/api/user/social-accounts` enforces 1:1 mapping (one account per workspace)
- GetLate sync preserves existing workspace links when re-syncing accounts

### Team Collaboration
- **Invite flow**: Owner enters email + role → invite created (7-day expiry) → invitee sees it in their invites → accept creates membership
- **Role enforcement**: Only owners can invite, remove members, and manage workspace settings
- **Member list**: Avatar initials, name, email, role badge with icons (Crown/Pencil/Shield)
- **Workspace creation**: Automatically adds the creator as "owner" in workspace_members

### Workspace Context & Filtering
- `WorkspaceProvider` wraps the dashboard layout
- `Workspace` interface includes `timezone` field
- Fetches workspaces on mount, persists selection in localStorage
- Dashboard, History, Calendar pages pass `workspace` query param to filter
- Create page reads `activeWorkspace` to pre-fill form + inject brand kit
- `WorkspaceSwitcher` in sidebar shows dropdown with all workspaces + inline "New workspace" form

## 11. Key Design Decisions

**Why Workspaces?**
Users often manage multiple businesses. Workspaces provide clean separation: each has its own business profile, brand kit, and batch history. Switching workspaces filters all views instantly.

**Why BYOK (Bring Your Own Key)?**
Users provide their own Gemini and fal.ai API keys. This eliminates platform-side API costs, gives users control over their usage, and avoids the complexity of metered billing.

**Why Caption Variations?**
A/B testing is critical for Instagram performance. Generating 3 alternatives at brief-generation time (virtually free — same Gemini call) gives users immediate options without regenerating.

**Why native Drag & Drop instead of a library?**
The calendar's drag-and-drop is simple (move post to day). HTML5 DnD API handles this natively with ~20 lines of code. Libraries like `dnd-kit` or `react-beautiful-dnd` would add bundle weight for no benefit.

**Why SSE instead of WebSockets?**
One-directional server -> client updates. SSE is native HTTP, natively supported in Next.js Route Handlers with zero extra setup. WebSockets require a separate server process.

**Why not polling?**
Polling hits the DB every 3 seconds per client regardless of whether anything changed. SSE pushes instantly when an image is ready.

**Why Cloudflare R2 for storage?**
Zero egress fees — images are served to users worldwide at no cost. R2 is S3-compatible so it uses the standard `@aws-sdk/client-s3`.

**Why Gemini URL context tool?**
When a website URL is provided, Gemini actually fetches and reads the page content (products, copy, brand tone) rather than just seeing the URL string. This produces dramatically more relevant design briefs.

**Why AES-256-GCM for API key encryption?**
BYOK keys must be decryptable (not hashed). AES-256-GCM provides authenticated encryption — both confidentiality and integrity verification. Each key gets a unique IV and auth tag.

**Why API keys at user-level but Instagram accounts at workspace-level?**
A user's Gemini/fal.ai keys are personal credentials — they pay for usage regardless of which business they're generating for. But Instagram accounts are per-business — each workspace publishes to a different IG account. This separation keeps billing simple while enabling multi-brand publishing.

**Why invite-based team collaboration instead of shared workspaces?**
Invites give owners explicit control over who accesses their workspace. The 7-day expiry prevents stale invites. Email matching ensures the right person accepts. This is simpler and more secure than share-by-link approaches.

**Why a separate approval workflow instead of direct publish?**
Teams need a review step before content goes live. The Draft → Approved → Scheduled → Published flow lets editors create and owners approve, preventing accidental publishing. It also gives scheduling flexibility — approve now, schedule for later.
